# 说明

C++ 类有一组由编译器自动处理的特殊成员函数。和资源管理相关的是下面五个，合称 Rule of Five（五法则）：

```
class Example {
public:
    ~Example();                          // 析构函数
    Example(const Example&);             // 拷贝构造
    Example& operator=(const Example&);  // 拷贝赋值
    Example(Example&&);                  // 移动构造
    Example& operator=(Example&&);       // 移动赋值
};
```

规则是：如果你自定义了其中任意一个，通常也要把另外四个一起写清楚（自己实现、`= default` 或 `= delete`）。

原因：自定义其中一个，等于告诉编译器“这个类的资源由我管理”。编译器就不会再按“成员逐个拷贝/移动”的默认方式放心生成其余函数，尤其是默认移动会被抑制。只写一半，很容易出现浅拷贝、重复释放，或右值本该移动却退化成拷贝。

更早的 C++98 只有前三个，叫 Rule of Three（析构、拷贝构造、拷贝赋值）。C++11 有了移动后，补上移动构造和移动赋值，变成五法则。

# 编译器默认会生成什么

一个什么都不写的类：
```
class MyClass {
public:
    int a;
    std::string b;
};
```

编译器可以自动生成：默认构造、析构、拷贝构造、拷贝赋值、移动构造、移动赋值。成员是 `std::string` 这种类时，拷贝/移动会调用 string 自己的对应函数，一般是安全的。

一旦你写了析构、拷贝或移动中的任意一个，默认移动通常不再生成。此时：
```
objs.push_back(MyClass());
```

即使传入右值，也可能走拷贝构造。详见 [拷贝构造与拷贝复制](/cpp/拷贝构造与拷贝复制/) 和 [移动构造和移动赋值](/cpp/移动构造和移动赋值/)。

# 只写析构为什么不够

类里有裸指针时，必须自己 `delete`，于是写了析构函数。

问题代码：
```
#include <iostream>

class MyClass {
public:
    MyClass() : b(new int(0)) {
        std::cout << "Constructor:         " << this << std::endl;
    }
    ~MyClass() {
        std::cout << "Destructor:          " << this << std::endl;
        std::cout << "Address of buf:      " << (void*)b << std::endl;
        delete b;
    }

public:
    int *b;
};

int main() {
    MyClass obj;
    MyClass obj2(obj);
    return 0;
}
```

运行结果：
```
Constructor:         0x7ffff3a00370
Destructor:          0x7ffff3a00390
Address of buf:      0x602000000010
Destructor:          0x7ffff3a00370
Address of buf:      0x602000000010
```

只写了析构，拷贝仍是编译器生成的浅拷贝，两个对象的 `b` 指向同一块内存，析构时重复释放。

正确做法是五件事一起处理：
```
class MyClass {
public:
    MyClass() : a(0), b(new int(0)) {}

    ~MyClass() {
        delete b;
    }

    MyClass(const MyClass& other)
        : a(other.a), b(other.b != nullptr ? new int(*other.b) : nullptr) {}

    MyClass& operator=(const MyClass& other) {
        if (this != &other) {
            int* new_b = (other.b != nullptr) ? new int(*other.b) : nullptr;
            delete b;
            a = other.a;
            b = new_b;
        }
        return *this;
    }

    MyClass(MyClass&& other) noexcept
        : a(other.a), b(other.b) {
        other.b = nullptr;
        other.a = 0;
    }

    MyClass& operator=(MyClass&& other) noexcept {
        if (this != &other) {
            delete b;
            a = other.a;
            b = other.b;
            other.b = nullptr;
            other.a = 0;
        }
        return *this;
    }

public:
    int a;
    int *b;
};
```

拷贝：新分配一份内存。  
移动：抢走指针，并把源对象置空。  
析构：只释放自己还拥有的那份。

# 不想拷贝时用 delete

有的类语义上不能拷贝，例如独占一块资源。这时不要“假装能拷贝”，直接删掉：
```
class MyClass {
public:
    MyClass() : b(new int(0)) {}
    ~MyClass() { delete b; }

    MyClass(const MyClass&) = delete;
    MyClass& operator=(const MyClass&) = delete;

    MyClass(MyClass&& other) noexcept
        : b(other.b) {
        other.b = nullptr;
    }
    MyClass& operator=(MyClass&& other) noexcept {
        if (this != &other) {
            delete b;
            b = other.b;
            other.b = nullptr;
        }
        return *this;
    }

private:
    int *b;
};
```

`= delete` 和 `= default` 的细节见 [default和delete](/cpp/default和delete/)。

# Rule of Zero

更好的做法是：尽量不要自定义这五个函数，让编译器自动生成，即 Rule of Zero（零法则）。

把裸指针换成智能指针、把文件句柄交给 RAII 包装类，本类就不再“手动管理资源”：
```
#include <memory>

class MyClass {
public:
    explicit MyClass(int value)
        : a(std::make_unique<int>(value)) {}

private:
    std::unique_ptr<int> a;
};
```

析构时 `unique_ptr` 会释放内存；移动由 `unique_ptr` 完成；拷贝被 `unique_ptr` 删除，本类也不能拷贝。你一个特殊函数都不用写。

发生内存泄漏的代码：
```
class MyClass {
public:
    MyClass(int value) : a(new int(value)) {}

private:
    int *a;
};
```

不会发生内存泄漏的代码：用 `std::make_unique<int>(value)` 代替 `new int(value)`。

# 一些总结

+ 类里没有原始资源：遵守 Rule of Zero，五个函数都不要手写。
+ 类里有裸指针、文件句柄、socket：必须面对 Rule of Five，五个都要有定义或 `= delete`。
+ 只写析构、不写拷贝/移动，是最常见的重复释放来源。
+ 写了拷贝或析构后，记得补移动，否则 `vector` 扩容、`push_back` 临时对象都会退化成拷贝。
+ 移动构造、移动赋值加上 `noexcept`，容器才能放心走移动。
+ 能用 `unique_ptr` / `shared_ptr` / `std::string` / `std::vector` 当成员，就不要自己 `new` / `delete`。
